## P0 — 논문과 코드가 서로 다른 말을 하는 부분 (기능 추가가 아니라 거짓말 수정)

### [ ] P0-1. τ를 데이터에서 자동으로 계산하게 만들기 (`train.py`, `screen.py` → 새 파일 `tac.py`)

**뭐가 문제인가:** 논문의 간판 주장은 "τ는 신호의 자기상관 시간에서 라벨 없이
자동으로 정해진다(τ = c·T_ac)"이다. 그런데 코드에서 τ는 그냥 **기본값 16으로
박아둔 숫자**다. 데이터를 보고 계산하는 코드가 아예 없다. 즉 지금까지의 모든
실험 결과는 "자동으로 정한 τ"가 아니라 "사람이 찍은 16"으로 나온 것이다.

**뭘 하나:**
- `screen.py` 안의 자기상관 계산 함수들(`acf_decay`, `local_descriptors`)을
  새 파일 `tac.py`로 빼서 하나의 진입점으로 만든다:
  `estimate_tac(...)` → raw / energy / envelope / zcr 각각의 T_ac와,
  최종 선택값 `chosen`을 **패치 단위**로 반환.
> **2026-08-02 수정:** 아래의 6.25패치 기준은 스펙 오류였다 (관측 불가능한
> u 자체의 수명; energy 계열은 u²을 추적하고 u²은 ×2 빨리 잊는다). 수정된
> D1 (CHECKLIST_v3 §A / `docs/tau.md`)이 이 절을 대체한다: u 스케일 환산
> (energy ×2), c = ln(1/eps), eps = 0.05.
- **확정 (D1): `chosen` = 파생열별 T_ac의 최솟값** — 가장 빨리 잊는 파생열이
  fast 수명의 추정치다. τ는 "빠른 성분의 수명"에 걸려야 한다. 코드에 정답이 이미 있다: 합성 데이터의 빠른 성분
  수명은 U_TAU=50스텝 = **6.25패치**이고, 16 ÷ 6.25 = 2.56 ≈ c=2.5. 즉
  하드코딩된 16은 estimator가 6.25 근처를 뱉어줄 때만 "우연히 맞았던 것"으로
  정당화된다. 주의: raw 신호의 ACF는 반송파(캐리어)가 잊히는 속도를 재는
  것이라 빠른 성분 u의 수명과 다를 수 있다. 어떤 열을 왜 골랐는지
  `docs/tau.md`에 적을 것.
- 4개 학습 스크립트 전부에 `tau=auto` 옵션 추가. **학습 데이터에서만**
  계산(평가 데이터 훔쳐보기 금지). `c`는 CLI 인자(기본 2.5). run JSON에
  `{tau_source, tac, c}` 기록. 수동 `tau=`는 부록 스윕용으로 유지.

**완료 기준:** `train.py mode=reg gate=1 xcov=1 tau=auto seed=0`이 돌아가고,
합성 데이터에서 선택된 T_ac가 **6.25패치 근처**로 나온다. 크게 어긋나면
그것 자체가 발견이다 — 기록하고, c를 몰래 조정해서 맞추지 말 것.
**후속 효과:** 자동 τ ≈ 16이면 기존 tau∈{4,64} 스윕 결과가 c-스윕으로
재활용 가능. 아니면 F4의 튜닝 주장이 근거를 잃으므로 스윕 재실행.

### [ ] P0-2. 숨어 있는 세 번째 손실 항 드러내기 (`train.py`, `hapt_train.py` 등)

**뭐가 문제인가:** 코드에 `F.relu(1.0 - z.std(0)).mean()`이라는 항이 **모든
모드의 손실에** 더해져 있다. 쉽게 말해 "임베딩의 각 차원이 찌그러지지 않게
분산을 1 이상으로 유지해라"라는 **붕괴 방지 안전장치**(VICReg 스타일)다.
그런데 논문의 손실 수식에는 이 항이 없다. 논문과 코드가 다른 수식을 쓰고
있는 것이다.

**뭘 하나:**
- 켜고 끄는 스위치 추가: `vfloor=1|0`. 계수는 이름 붙은 상수로. run
  태그/JSON에 기록.
- 끄고 돌려보는 실험 1개: `vfloor=0`, gate+xcov, 3시드 — 이 항이 실제로
  무슨 일을 하는지 알아야 "무엇이 붕괴를 막는가"를 주장할 수 있다.
- **확정 (D7, 규칙):** vfloor=0에서 RankMe가 붕괴를 보이면 → 논문 수식에
  세 번째 항으로 편입 / 안 보이면 → vfloor=0 기본값으로 하고 제거. 결과가
  나오면 기계적으로 적용. `git log -S "relu(1.0"`으로 도입 시점·사유 기록.
- **이것 때문에 논문 문장 하나를 고쳐야 한다:** F3의 "xcov만 쓰면 모델이
  slow 블록을 *비워서* 벌점을 회피한다"는 표현 — 이 안전장치가 분산≥1을
  강제하는 한 블록은 비워질 수 없다. 실제로 일어난 건 "비움"이 아니라
  "regime과 무관한 잡동사니 분산으로 채움"이다. 문장 수정.

**완료 기준:** 코드의 손실 = 논문의 손실 (또는 논문에 세 번째 항이 추가됨).
ablation 결과가 `runs/`에 존재.

### [ ] P0-3. 두 줄기(Reg / NCE)를 깨끗하게 정의하기 (`train.py`)

**뭐가 문제인가:** 논문은 "HGLP-Reg와 HGLP-NCE는 붕괴를 막는 방식이 다른 두
줄기"라고 팔 계획이다(Reg는 EMA가, NCE는 negative 샘플이 막음). 그런데
코드의 `mode=cpc`는 실제로는 **InfoNCE + EMA 타깃 + 분산 안전장치**를 전부
쓴다. 즉 지금의 "NCE"는 독립된 줄기가 아니라 Reg 줄기에서 거리 함수만 바꾼
것이다. 이대로면 "negative가 붕괴를 막는다"는 주장을 할 수 없다 — EMA와
안전장치가 켜져 있는데 셋 중 누가 막았는지 알 수 없으니까.

**뭘 하나:**
- 모드 이름 변경: `nepa`→`reg`, `cpc`→`nce` (옛 이름은 한 커밋 동안 별칭
  유지 — 기존 결과 파일을 읽는 스크립트가 안 깨지게).
- 손실과 타깃을 독립 옵션으로 분리: `loss=reg|nce` × `target=ema|online`.
  - `target=ema` = 천천히 따라오는 복사본 인코더가 타깃 생성 (지금 방식)
  - `target=online` = 같은 인코더가 실시간으로 타깃 생성
- **확정 (D2):** `target=online` = **양방향 그래디언트(SimCLR식), EMA 없음,
  stop-grad 없음** — 가장 단순한 형태. 불안정하면 ⛔ 멈추고 보고, 자율로
  stop-grad 후퇴 금지.
- 공식 조합: **HGLP-Reg = `reg+ema`** / **HGLP-NCE = `nce+online`**.
- **공짜 소득 (코드 확인됨):** `runs/`에 옛 cpc 실험(`cpc_g0_d0`,
  `cpc_g1_d0`, `cpc_g1_d1`, 각 3시드)이 이미 있다. 재정의 후 이것들은
  정확히 `nce+ema` **대조군** 셀이 된다. 지우지 말고 재실행하지도 말고,
  태그 이전 도구(P1-1)로 이름만 바꿀 것. 새로 돌릴 건 `nce+online` 셀들과
  한 번도 안 돌린 `nce xcov-only`뿐이다.

**완료 기준:** 논문의 손실 비교표가 run JSON에서 그대로 채워진다. 줄기별
"붕괴 없음" 주장이 RankMe 수치 + **vfloor=0 대조군**으로 뒷받침된다.

### [ ] P0-4. 시드가 데이터를 바꾸는가 — 결정하고 문서화 (`train.py`)

**뭐가 문제인가:** `make_dataset(1_000_000, seed=0)` — 시드 인자를 받고도
데이터는 항상 seed=0으로 고정이다. 즉 "3시드 결과"는 3개의 다른 데이터가
아니라 **같은 데이터에 초기화만 3번 다르게** 한 것이다. 코드에는 "의도된
설계"라는 주석이 이미 있으니 절반은 처리됐고, 빠진 건 논문 프로토콜에 이
사실을 밝히는 한 문장이다 ("오차 막대는 학습의 확률성만 반영, 데이터
재추출은 반영 안 함").

**확정 (D3): (a)** — `make_dataset(..., seed=seed)`로 수정, 합성 오차 막대
전부 재생성. 재실행은 P4-1/야간 매트릭스에 통합해 이중 학습 방지. 프로토콜
문장은 "시드가 데이터 재추출까지 바꾼다"로 갱신.

**완료 기준:** 논문 문장과 코드가 일치. 재실행 범위가 글로 적혀 있음.

### [ ] P0-5. 스크린이 '결맞은 주기' 신호를 걸러내게 만들기 (`screen.py`)

**뭐가 문제인가 (2겹):**
1. 주기 성분 검사가 아예 없다. 더 나쁜 건, 기존 C2 검사("먼 미래가 예측
   되는가")는 순수 주기 신호에서 **강하게 통과**한다 — 주기는 완벽히 예측
   되니까. 즉 지금 스크린은 논문이 걸러낸다고 주장하는 바로 그 신호를
   환영한다.
2. **더 교묘한 함정:** `screen()`은 윈도우를 패치 평균(`W.mean(-1)`)으로
   접어서 본다. 8샘플 평균은 사실상 저역통과 필터라서, 주기 ~10스텝짜리
   합성 반송파 같은 **짧은 주기 성분을 계산 전에 지워버린다.** 이 위에서
   주기 검정을 돌리면 짧은 주기 confound를 통과시키는 구멍 난 스크린이 된다.

**뭘 하나:**
- `check_coherent_periodic(series)` 추가: (a) ACF 진동의 포락선이 줄어드는지
  검사 (줄면 = 잊는 신호 = 통과 / 안 줄면 = 영원한 주기 = 탈락),
  (b) Fisher's g-test로 스펙트럼에 뾰족한 선이 있는지 검사 — 단
  **패치 평균이 아니라 원본 샘플 레벨 신호에서** 돌릴 것 (+ 파생열에서도).
- 이걸 **Check 1**로 배선 — T_ac/gap 계산 *전에* 실행, 걸리면 이유
  `coherent_periodic`으로 즉시 탈락.
- 기존 C1/C2/C3은 Check 2의 구성요소로 번호 재조정.

**완료 기준 (회귀 검사):** HAPT / 합성 / PTB-XL / XJTU의 판정이 현재
`screen_results.json`과 같은 편에 남아 있음 (PTB-XL의 세분화는 P0-6에서
허용된 예외). 주기 성분을 주입한 대조 신호는 `coherent_periodic`으로 탈락.
⛔ **중단 지점: 합성 데이터가 Check 1에서 탈락하면 멈추고 보고.** 합성
신호는 sin 반송파 + ±5% 주파수 변조라, OU 지터의 위상 확산이 ACF 포락선을
충분히 빨리 죽이는지는 임계값 문제다. 스크린이 자기 실험대를 기각하면 그
아래 모든 판정을 믿을 수 없다 — 여기부터 고칠 것.

### [ ] P0-6. 윈도우 적합성 검사를 L이 아니라 Δ_max와 비교 (`screen.py`)

**뭐가 문제인가:** 현재 C3은 `tau_slow < L`(윈도우 길이 256패치)을 검사한다.
그런데 진짜 중요한 비교 대상은 **가장 긴 학습 호라이즌 Δ_max = 128패치**다.
느린 요인이 Δ_max와 비슷한 스케일로 변해야 "slow 분리"가 되고, 훨씬 느리면
"static 분리"로 퇴화한다 (그래도 작동은 하지만 논문의 주장 이름이 달라짐).

**뭘 하나:**
- 비교 대상을 Δ_max로 교체. 판정을 3단계로:
  `SUITABLE (slow)` / `SUITABLE (static-only)` / `UNSUITABLE`.
- PTB-XL이 `static-only`로 나오는 게 **정답**이다 (10초 기록 안에서 진단은
  불변이니까). 실패가 아니라 올바른 분류.
- **`screen_model.py`를 재활용할 것** — "짧게 학습한 모델로 먼 미래 임베딩이
  얼마나 예측되는지" 재는 기계가 이미 구현돼 있다 (SHORT=2, LONG=64).
  호라이즌 목록만 늘려서 "예측력이 Δ_max까지 계속 오르나, 일찍 포화하나
  (= dwell ≫ Δ_max)" 진단에 쓰면 된다. 새로 만들지 말 것.

**완료 기준:** 스크린이 HAPT(slow)와 PTB-XL(static-only)을 구분한다.

### [ ] P1-3. `L_dcor` → `L_xcov`
`dcor`는 통계학의 distance correlation(Székely)과 이름이 겹치는데 우리
구현은 그게 아니라 제곱 교차공분산이다. CLI 플래그도 `dcor=`→`xcov=`
(별칭 한 커밋 유지).

### [ ] P1-4. HEPA 오귀속 전면 수정 (산문 전체)
HEPA 원문 대조로 확정된 사실: HEPA는 (a) `(t, t+Δ]` **구간 요약** 타깃
(양방향 인코더 + attention pooling), (b) **가중치 공유·공동 학습** 타깃
인코더 (EMA 없음, stop-grad 없음), (c) 붕괴 방지는 **SIGReg**, (d) 손실은
**L1**. 우리는 **t+Δ 단일 시점(point) 타깃 + EMA + L2** — 넷 다 다르다.
"as in HEPA"라는 표현을 전부 대비 서술로 교체. **스코프 (사용자 결정):**
4중 대비는 related works 한두 문장으로; Method에는 타깃 형태(point vs
구간요약) **한 문장만** 유지 — 비교가 아니라 게이트 논리의 전제이므로.
대상 파일: README, HANDOFF, `report.tex`, `report_3p.tex`, `plan.tex`.

## P3 — 새 실험 모듈

### [ ] P3-1. Variance-only regime (`datagen.py`)
`regime_mode=freq|variance` 옵션: `variance` 모드는 반송파 주파수와 평균은
그대로 두고 **OU 진폭만** regime별로 바꾼다.
- ⚠️ **코드 함정:** `datagen.py`의 자기 테스트(`__main__`)에 "regime별 분산
  비율 < 1.2" assert가 있다 — variance 모드는 이걸 **설계상 위반**한다.
  assert를 `regime_mode`에 조건부로 바꾸지 않으면 자기 테스트에서 죽는다.
- gate+xcov를 **두 줄기 모두**, 3시드, layernorm 켠/끈 (P2-3) 조건으로.
- 실행 전 예측을 기록해둘 것: Reg(조건부 평균 학습기)는 고전할 수 있고
  NCE는 버틸 수 있다.
**완료 기준:** 2줄기 × 3시드 결과가 `runs/`에 존재. 논문에 결과 문장 1개:
"분산으로만 구분되는 regime에서 분리 확인 여부 + 줄기 간 차이 유무."

### [ ] P3-2. 결맞은 주기 confound (`datagen.py`)
`periodic_amp`, `periodic_coh`로 조절 가능한 주기 성분 주입. 용도:
(a) P0-5의 탈락 검증용 대조 신호, (b) 선택: 결맞음 시간이 Δ_max를 넘는
순간 phase 요인이 z_fast → z_slow로 이주하는 스윕.

### [ ] P3-3. 구간요약 타깃 ablation (`train.py`)
`target_shape=point|interval` 옵션. `interval` = `(t, t+Δ]`를 양방향으로
인코딩 + attention pooling = HEPA 타깃. Reg 줄기만.
목적: "게이트는 point 타깃을 요구한다"를 논증에서 측정으로 승격.
**완료 기준:** Part-1 표에 한 행. interval에서 분리가 측정 가능하게
나빠지거나, 안 나빠지면 논증을 다시 쓴다.

### [ ] P3-4. Shift 강건성 (`shift_eval.py`) — **P3 최우선**
학습은 그대로; 평가 시 **fast만 교란** (OU 수명 50→{20,150}, OU 스케일
×{0.5,2}, 노이즈 레벨). regime 프로세스는 불변. probe는 깨끗한 데이터로
학습, 교란된 데이터에서 평가, z_slow vs z_full 비교.
**완료 기준:** 성능 낙차 그림/표. Part 2 전체를 지탱하는 단일 결과 —
초록에 이 결과를 기다리는 자리표시 문장이 있다.

### [ ] P3-5. Label efficiency (`label_eff.py`)
probe 라벨 {1%, 10%, 100%} × {z_slow, z_full}, 합성 + HAPT.
**공정성 필수:** ridge/logistic의 λ를 **양쪽 모두** 검증 분할에서 튜닝 —
"차원이 적어서 이겼다"는 반론 차단.

### [ ] P3-6. HI 품질 (`hi_metrics.py`) — 선택, 학위논문 다리
run-to-failure 시퀀스에서 z_slow 궤적(1주성분)의 monotonicity /
trendability / prognosability (Coble & Hines) vs z_full 궤적. 시간 없으면
생략.
