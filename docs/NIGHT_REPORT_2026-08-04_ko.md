### 2.2 핵심 구현 결정 6가지

**① B4 앵커 샘플링 — 교차 검토가 잡은 버그를 실제로 고침**
프로토콜 초안의 `[min_context, L − Δ_max)`는 상한이 v1과 같아서 `pos[128:256]`이 학습되지 않았습니다. 구현은 **Δ를 먼저 뽑고 앵커 상한을 그 Δ에 맞춰** 정합니다:
```python
anchors = rng.integers(min_context, Lw - dmin, (batch, n_anchor))
hi = np.minimum(dmax, Lw - 1 - anchors)          # 이 앵커에서 가능한 최대 Δ
deltas = exp(log-uniform between dmin and hi)     # 로그 균등, 격자 없음
```
작은 Δ가 앵커를 창 끝까지 밀어주므로 전 위치가 학습됩니다.

**② B5 타깃 — 수용장 제한**
```python
starts = (anchor + Δ - w)[:, None] + arange(w)
ztgt = tenc(xb[batch_idx[:, None], starts])[:, -1]   # 조각을 0부터 인덱싱
```
조각을 **0부터 인덱싱**하는 게 핵심입니다(절대 인덱스 아님). `pos[k]`가 "k개 과거를 가진 위치"와 짝지어 학습되기 때문에, 짧은 조각의 마지막 토큰에는 `pos[w−1]`이 맞습니다.

**③ 손실 × 타깃인코더 직교 축 (NCE 구현)**
```python
loss_kind  = "reg" | "nce"      # L2 vs InfoNCE
target_enc = "ema" | "online"   # EMA 복사본 vs 같은 인코더(양방향 그래디언트, D2)
```
`tenc = tgt if use_ema else enc`로 타깃 인코더를 고르고, online이면 `no_grad`를 걸지 않아 양방향 그래디언트가 흐릅니다. EMA 갱신도 `use_ema`일 때만 합니다.

**④ NCE 네거티브 — 같은 윈도우 제외**
같은 윈도우에서 나온 쌍들은 **느린 인자를 공유**합니다. 이를 네거티브로 쓰면 "느린 상태가 같은 표현끼리 밀어내라"가 되어 빠른 정보를 보상하게 됩니다 — 우리 목표의 정반대죠. 그래서 마스킹이 기본값입니다(`mask_same_window=True`). 윈도우 인덱스 구조가 매 스텝 동일하므로 마스크는 루프 밖에서 한 번만 계산합니다.

**⑤ A3 정규화 — 학습 그룹에서만 적합**
채널당 평균·표준편차를 **학습 피험자/환자에서만** 구해 전체에 적용합니다. 채널 혼합 레이아웃(`patch × axis` 평탄화)에서 축별 열을 골라내야 해서 인덱싱이 까다로웠고, 여기서 버그가 하나 났습니다(6절).

**⑥ C1 다위치 프로브**
라벨이 있는 **모든 위치**에서 z를 뽑아 그 위치의 라벨로 채점합니다. 끝점만 보는 지름길을 막고, 위치별 성능 곡선과 전환 궤적을 얻습니다. 실데이터는 표본이 37만개까지 나와서 6만개로 서브샘플링합니다(위치들이 강하게 상관돼 있어 추정치는 거의 안 변합니다).

## 3. 발견 1 — E1(τ 추정)이 HAPT에서 깨짐

E3(HAPT τ를 L=256에서 재추정)을 실행하자 **τ = 290 패치**라는 말이 안 되는 값이 나왔습니다(윈도우가 256인데 τ가 290).

**원인:** HAPT는 중력/자세라는 **느린** 성분이 모든 축의 ACF를 압도합니다. E1의 "가장 빨리 잊는 계열의 최솟값" 규칙이 fast(보행 ~1초)를 찾는 대신 slow(자세)를 잡아버립니다.

| 추정 방식 | chosen | τ | L=256에서 τ 바깥 horizon |
|---|---|---|---|
| 축별 raw (E1 현행) | 96.8 p | 290 p | **0개 (무효)** |
| magnitude (legacy 방식) | 14.2 p | **42.7 p** | 2개 ✓ |
| 고역통과 후 축별 | 8.0 p | 24.0 p | 2개 ✓ |

**시사점:** magnitude가 회전 불변이라 자세를 지우는 게 τ 추정에서는 **오히려 장점**이었습니다. E1을 "축별 raw 최솟값"에서 **"고역통과 후 축별" 또는 magnitude**로 수정해야 합니다. 실험은 τ=40(magnitude 근사)으로 진행했습니다.

## 4. 발견 2 — 실데이터 분리와 shift robustness

### 4.1 HAPT: 분리 성공

held-out 피험자, 위치별 다위치 프로브(reg+ema, 단일 시드 기준):

| 블록 | 활동 F1 | leak (accmag R²) |
|---|---|---|
| **z_slow** | **0.809** | **0.300** |
| z_full | 0.875 | 0.963 |

z_slow가 활동을 거의 z_full만큼 담으면서 fast는 대부분 배제. **정직한 다위치 프로브로도 legacy v1(0.71)보다 강합니다.**

### 4.2 HAPT: shift는 미결 (교란 설계 문제)

노이즈·스케일 교란에서 z_slow와 z_full이 거의 똑같이 열화했습니다(잔존율 38% vs 35%). **진짜 음성이 아니라 제 교란이 잘못된 것입니다** — 일반 교란은 느린 인자(활동)까지 같이 망가뜨려서 메커니즘을 테스트하지 못합니다. fast만 겨냥하고 slow는 보존하는 교란(예: time-warp = 보행 속도 변경, 활동 유지)이 필요합니다.

### 4.3 PTB-XL: shift 성공 ★

옵션 C의 가설(static 케이스는 다르게 행동)이 맞았습니다.

| 교란 | z_slow 잔존율 | z_full 잔존율 | 해석 |
|---|---|---|---|
| **게인(scale)** | **88%** | 71% | **z_slow 승. 강한 교란에서 절대값 역전(0.613 > 0.512)** |
| 노이즈 | 60% | 55% | z_slow 근소 우위 |
| baseline wander | 74% | 77% | z_full 근소 우위 |

**wander 결과가 오히려 중요합니다.** wander는 **느린** 드리프트라서 z_slow로 들어갑니다. 즉 z_slow가 불리해지는 게 맞고, 이건 버그가 아니라 **z_slow가 진짜로 느린 성분을 담는다는 증거**입니다. 동시에 "z_slow는 그냥 16차원이라 강건한 것 아니냐"는 대안 설명을 반증합니다 — 저차원이기만 하다면 wander 비대칭이 나올 이유가 없습니다.

## 5. 발견 3 — NCE 도입으로 스템 순위 역전

### 5.1 27런 매트릭스 (3스템 × 3시드 × 3데이터셋)

| | slow-kept ↑ | leak ↓ | z_fast가 fast를 담는가 ↑ |
|---|---|---|---|
| **합성** | | | |
| reg+ema | 0.601±0.058 | +0.083±0.004 | 0.875 |
| **nce+ema** | **0.966±0.004** | **+0.003±0.075** | 0.871 |
| nce+online | 0.971±0.001 | +0.549±0.036 | 0.883 |
| **PTB-XL** | | | |
| reg+ema | 0.689±0.009 | +0.422±0.056 | 0.959 |
| **nce+ema** | **0.780±0.001** | **+0.344±0.050** | 0.928 |
| nce+online | 0.753±0.012 | +0.293±0.020 | 0.689 |
| **HAPT** | | | |
| reg+ema | 0.764±0.035 | +0.192±0.084 | 0.924 |
| **nce+ema** | **0.826±0.001** | **+0.016±0.011** | 0.646 |
| nce+online | 0.786±0.034 | +0.006±0.002 | 0.246 |

**nce+ema가 reg+ema를 세 데이터셋 모두에서 두 지표 다 이깁니다.** 단일 시드에서 지표가 엇갈렸던 건(leak 0.118 vs 0.074) 오차 막대를 붙이니 사라졌습니다. 즉 **D4를 다시 열 필요 없이, 원래 규칙이 nce+ema를 지목**합니다.

부수적으로 nce+ema는 **재현성도 훨씬 높습니다** — slow-kept 표준편차 ±0.001~0.004 (reg는 ±0.009~0.058).

### 5.2 nce+online의 부분 공허성

D2가 정의한 정식 NCE 스템(online 타깃)은 leak이 가장 낮지만, **낮은 이유가 다릅니다.** HAPT에서 z_fast가 fast를 **0.246밖에 못 담습니다**(nce+ema 0.646, reg 0.924). 즉 "z_slow에 안 샌 것"이 아니라 **"어디에도 fast가 제대로 안 담긴 것"**에 가깝습니다 — v1에서 nce+online을 탈락시켰던 바로 그 실패 양상입니다. 반면 nce+ema는 leak이 낮으면서 z_fast는 fast를 제대로 담습니다. **이게 진짜 분리입니다.**

### 5.3 해석 — B5와 손실의 상호작용

reg+ema가 왜 약해졌는지가 중요합니다. **게이트 문제가 아닙니다** — 합성에서 z_full조차 0.651이라 임베딩 전체에 regime이 없습니다.

추정 메커니즘: 수용장 제한 타깃(B5)은 약하게만 예측 가능한데, **L2는 이럴 때 조건부 평균(≈상수)을 예측하는 게 최적**이라 약한 느린 신호를 인코딩할 압력이 거의 없습니다. 반면 **InfoNCE는 판별을 강요**당하므로 약한 느린 신호도 순위 매기기에 이득이 됩니다.

이건 논문에 쓸 만한 관찰입니다: **"타깃 수용장을 제한하면 손실 형태가 중요해진다. 회귀는 약한 느린 신호를 놓치고, 대조는 잡는다. 단 타깃 안정화(EMA)가 없으면 배제가 공허해진다."** B5·B6·D2가 상호작용한다는 걸 27런으로 보인 셈입니다.

## 6. 버그·위생 수정

| 항목 | 내용 | 영향 |
|---|---|---|
| **정규화 축 인덱싱 버그** | 채널 혼합 레이아웃에서 축별 열을 `a + per*k`로 골랐는데 실제로는 `a + n_ax*k`가 맞음 | 즉시 크래시 → 수정. 결과에 영향 없음 |
| **가변 윈도우 길이** | 앵커 샘플링이 상수 `L=256`을 써서 PTB-XL(L=100)에서 깨짐 | 데이터의 실제 길이 `Lw` 사용으로 수정 |
| **프로브 표준화 (위생)** | z_slow의 표본간 std가 0.019로 작아 L2 규제 프로브가 불리 | 모든 프로브에 `StandardScaler` 추가 |

**표준화가 결과를 바꾸지 않았음을 검증했습니다.** reg+ema slow-kept가 0.507 → 0.535로 거의 그대로였습니다. 즉 5절의 결과는 측정 아티팩트가 아닙니다. (수정 자체는 정당한 위생 조치라 유지하고 실데이터도 재실행했습니다.)

## 8. 당신이 결정할 것

### 결정 ① — 스템 (D2와 충돌)

D4는 nce+ema를 지목하는데, D2는 NCE 스템을 `target=online`으로 정의하고 있습니다.

- **(가) nce+ema 채택** — 증거 만장일치, D4 규칙과 일치. D2의 "HGLP-NCE = nce+online" 정의를 수정하고, nce+online은 **ablation**("온라인 타깃은 배제를 공허하게 만든다")으로 보고. **← 추천**
- **(나) D2 유지** — 정식 두 스템(reg+ema, nce+online)만 싣고 nce+ema는 대조로. 규칙엔 충실하나 가장 좋은 결과를 각주로 미는 셈.
- **(다) D2를 ⛔로 처리** — 엄밀히 D2의 ⛔ 조건("불안정")은 아닙니다. nce+online은 학습이 불안정한 게 아니라 품질이 낮은 것.

### 결정 ② — HAPT shift 재시도 여부

- **(가) time-warp 교란 구현** — 보행 속도를 바꿔 fast만 겨냥, 활동은 보존. HAPT에서도 shift를 보일 가능성. 반나절 리스크.
- **(나) PTB-XL shift로 충분** — 이미 깨끗한 결과가 있으니 HAPT는 분리 증거로만 쓰고, shift는 PTB-XL + 합성으로. **← 마감 관점에서 추천**
