## A. 데이터

### A1 — 윈도우 길이 & 스트라이드 ✅(합성) / ⛔(HAPT) / 🔁(스트라이드)

게이트는 τ **안쪽**에 최소 2개, **바깥쪽**에 2개의 학습된 horizon이 필요하다
(초안 규칙, `docs/tau.md`): Δ 집합이 τ를 걸치고(straddle), τ ≈ c·T_ac(min)여야
한다. 따라서 윈도우는 horizon을 ≈ T_ac(max)까지 담을 만큼 길어야 한다.

- **Synthetic:** L = 256 패치 (2048 스텝). 근거: Δ_max = 128 p가 dwell의
  ~0.34배, fast 수명의 ~20배 — τ≈15.7 기준 안쪽 2개, 바깥 3개. straddle 규칙
  만족. **유지.** ✅
- **스트라이드 (평가 윈도우):** probe 평가용은 겹치지 않게(disjoint) —
  leak-freedom(C3)의 필수조건. 학습 윈도우는 겹쳐도 됨; 겹침 비율은
  **임의 → 스윕**(v1은 랜덤 시작 오프셋). 🔁
- **HAPT:** v1은 L = 128 (10.24 s), Δ_max = 32 p. EDA 판정: auto-τ (39.7 p)가
  Δ_max 바깥 ⇒ τ 바깥 horizon 0개 ⇒ 게이트가 절대 안 닫힘; L = 256 (20.5 s)은
  **불가능** — 활동 세그먼트의 70%가 윈도우보다 짧고, 윈도우의 92%가 경계를
  가로지름. 즉 HAPT는 자기 활동 세그먼트보다 긴 윈도우 없이는 straddle Δ 집합을
  담을 수 없다. ⛔ **결정 필요:** (a) HAPT를 L≈128로 유지하되 영원히 "τ 바깥
  0개" 데이터포인트로만 취급(분리 주장이 아니라 negative-config로 보고); (b)
  EDA(VOID/전환 오염 + 순간 판독 가능한 자세)를 근거로 HAPT를 slow-factor
  테스트베드에서 제외하고 shift/label-efficiency probe에만 사용; (c) HAPT를
  정적 자세 부분집합(SIT/STAND/LAY만)으로 제한 — 최소한 "slow"=자세가 잘 정의됨.
  **추천: (b)** — EDA가 HAPT 활동 라벨이 대체로 end-region 판독임을 보였으므로,
  L과 무관하게 slow 통합을 깨끗이 입증할 수 없다.

### A2 — 라벨 정책 ⛔(HAPT) / ✅(PTB-XL, XJTU)

v1 HAPT: `per[end]`(end-point 샘플 라벨), 클래스 1–6 유지, **end-point**가
VOID(0)나 전환(7–12)인 윈도우는 조용히 스킵 — 그러나 *유지된* 윈도우도 스팬
중간에 VOID/전환 샘플을 포함할 수 있다(57%가 그럼: VOID 25%, 전환 20%, 다른
활동 12%; `docs/eda/README.md` STEP 4). 문서화 안 된 선택 3개가 묶여 있다:

1. **라벨 위치** — end-point vs 위치별. ⛔ **결정 필요.** 옵션: (i) end-point
   라벨(v1) — 그러나 EDA가 이건 국소적으로 읽힌다고 보임, slow 주장 약화; (ii)
   **위치별 라벨** — 각 앵커 위치를 그 위치 자신의 라벨로 probe, causal 인코더와
   부합하고 통합을 정직하게 측정; (iii) 스팬 다수결 — 전환을 숨김. **추천: (ii)**
   위치별, "윈도우가 한 세그먼트 안에 완전히 들어감" 제약과 결합. HAPT 수치를
   "end-region 판독"이 아니라 "slow-factor 판독"으로 만드는 유일한 변경.
2. **VOID / 전환 클래스** — 조용히 버리지 말 것. ⛔ **결정 필요.** 옵션: (i)
   VOID나 7–12를 포함한 윈도우 전부 제외(클린 부분집합만 — 윈도우의 ~57% 손실,
   n≈1250); (ii) 전환 클래스 7–12를 자체 라벨로 유지(12클래스 문제); (iii) v1의
   end-point 필터(기각 — 스팬 중간 오염을 미문서화로 남김). **추천: (i)** 분리
   주장에는 클린 부분집합만, 제외 비율은 별도 보고해 제약을 명시.
3. **세그먼트 경계를 넘는 윈도우** — 현재 허용(그게 오염 그 자체). 위 (ii)+(i)와
   함께면 금지: 윈도우는 단일 활동 세그먼트 안에 있어야 함. 윈도우는 파일/피험자
   경계를 절대 안 넘음(v1 루프가 파일 단위 — 감사에서 0 확인). ✅ (파일 경계 부분).

- **PTB-XL:** 기록당 라벨 1개, 10 s 내내 일정. 유지. NORM-vs-전체 풀링이 거칠지만
  데이터셋 자체의 입도임을 명시. ✅
- **XJTU:** 스냅샷당 life-fraction, 80 ms 윈도우 내 일정. 유지; "life" = 스냅샷
  인덱스 / (n−1), 정규화 위치이지 물리 RUL 아님을 명시. ✅

### A3 — 정규화 ⛔ / ✅

v1: HAPT/PTB-XL/XJTU 입력에 **윈도우별·축별 시간축 z-score**
(`(w−w.mean(0))/w.std(0)`), 추가로 인코더 출력에 `F.layer_norm`(B2 참조). EDA/
읽기가 드러낸 두 문제:

- 윈도우별 z-score는 **중력 방향을 지운다** — SIT/STAND/LAY(모두 ≈1 g, 방향만
  다름)를 구분하는 바로 그 자세 단서. 또 **윈도우 간 비교가능성을 파괴**하므로
  절대 레벨로 정의된 slow 인자는 살아남을 수 없다. RevIN식 윈도우별 정규화는
  예측 *분포이동 강건성*을 위한 설계 — slow 레벨 보존이 필요한 우리 목표와 정반대.
- ⛔ **결정 필요(정규화 범위):** (i) **데이터셋 전역** 표준화(학습 split에 대해
  채널당 평균/표준편차 하나) — 중력 방향과 윈도우 간 레벨 보존, 추천; (ii)
  기록별(피험자/환자/베어링) — 기록 내 레벨 보존, 피험자 간 오프셋 제거; (iii)
  윈도우별(v1) — 위 이유로 기각. **추천: (i)** 데이터셋 전역, 채널당, 학습 split
  에만 적합. Synthetic: v1에서 **raw**(비표준화) 투입 — 진폭 단서가 인코더에 도달;
  고정 스케일로 생성되므로 raw 유지. ✅

## B. 학습 태스크

(`legacy/train.py` 현재 상태 읽기: `P=8, L=256, D_MODEL=96, D_Z=64,
OFFSETS=[1,4,16,64,128], W=4.0, EMA=0.996, STEPS=3000, BATCH=64, LR=3e-4,
n_anchor=8`.)

### B1 — 앵커 범위 ⛔ (확인된 버그) / 추천 제시

v1: `anchors = rng.integers(64, L−max(OFFSETS)) = [64, 128)`. 읽기로 확인된 결과:

- 위치 **[0,64), [128,256)는 절대 앵커가 안 됨** ⇒ 그 위치 임베딩
  `pos[128:256]`(및 `pos[0:64]`)는 **그래디언트를 못 받음.**
- 타깃은 `anchor+Δ ∈ [65, 256)`, 즉 **미학습 위치 임베딩 범위**까지 올라가고,
  EMA 타깃 인코더가 그 미학습 임베딩을 상속 — 장-Δ 타깃이 부분적으로 랜덤 위치
  잡음.
- 평가는 위치 **255**를 probe(`enc(x)[:,-1]`) — 앵커 범위 밖의 완전 미학습 위치
  (C1 참조). 3중 불일치.

⛔ **결정 필요(수정):** (a) **상대 위치 인코딩**(RoPE / relative bias) — 어떤
절대 위치도 특별하지 않아 모든 앵커/타깃 위치가 학습됨, 가장 깔끔, 버그 클래스
전체 제거; (b) 유효 전 범위 `[Δ_context_min, L−max(OFFSETS))`에서 앵커 샘플링
AND 모든 probe 위치가 학습되게 보장; (c) 학습대가 덮도록 L 축소. **추천: (a)**
상대 위치 — B3(horizon 일반화)도 직접 지원하고 "어느 위치를 probe하나"를 비쟁점화.

### B2 — 출력 정규화 ⛔ / 추천 제시

v1: `F.layer_norm(out, (D_Z,))`를 **64차원 전체**에 공동 적용. slow 블록의
스케일을 fast 블록의 내용에 결합(고분산 z_fast가 z_slow를 재스케일)하여 블록
독립성과 모순 — xcov 페널티가 따로 강제하려는 그 속성.

⛔ **결정 필요:** (i) **블록별 LayerNorm**(z_slow, z_fast 독립 정규화) — 교차
결합 없이 각 블록 자기정규화; (ii) **출력 정규화 없음**, 타깃 인코더 EMA + xcov에
스케일 제어 위임; (iii) 블록 분할 *전에* D_MODEL 트렁크 정규화. **추천: (i)**
블록별 정규화 — 최소 변경, 교차 결합 직접 제거, probe 입력으로서 각 블록 사용성
보존.

### B3 — Δ 조건화 ✅ 결정(연속) / 근거

v1: `nn.Embedding(len(OFFSETS), 16)` — **Δ로 인덱싱된 5개 독립 벡터.** 이것은
CPC의 per-k 헤드의 변장: horizon 간 보간 없음, Δ=16이 4와 64 "사이"라는 개념
없음, 미관측 horizon 표현 불가.

**결정:** **연속 조건화**로 교체 — `log2(Δ)`(스칼라)를 작은 MLP를 통해, 또는
`log Δ`의 사인 임베딩을 predictor에 투입. ✅ 근거: **미관측 horizon으로의
일반화**를 산다 — 논문의 핵심 "horizon은 공짜 감독 축" 주장이 요구하는 바로 그것
(이산 per-Δ 헤드로는 축이 연속이라 주장 불가). τ가 격자 Δ에 스냅되지 않고 임의
실수(A1/D1)가 되게도 함. (어느 인코딩 — MLP(logΔ) vs 사인 — 은 **임의 → 스윕**.🔁)

### B4 — 앵커 / Δ 샘플링 밀도 🔁 → 더 조밀하게 결정

v1: 앵커 8개 × Δ 1개 = **256 위치 forward pass에서 (앵커,Δ) 쌍 8개** — forward
pass의 ~97% 낭비(256 중 8 위치만 감독; 앵커마다 랜덤 Δ 1개라 Δ축은 윈도우당 8회
샘플).

**결정:** **조밀하게** 샘플 — 샘플된 각 앵커에 대해 **모든**(또는 큰 랜덤
부분집합) horizon Δ 사용, 윈도우당 앵커도 더 많이. 목표 ≈ (많은 앵커) × (전체 Δ
집합) 쌍/forward pass. ✅ 방향. 정확한 개수(n_anchor, 전체-Δ vs 부분집합)는
throughput/분산 트레이드오프로 **임의 → 스윕**. 🔁 근거: 게이트 신호는 *고정
앵커에서 Δ에 걸친 대비*인데, 앵커당 Δ 1개는 스텝당 앵커 내 Δ 대비를 거의 못 줌.

### B5 — 타깃 정의 ⛔ **결정 필요 — 리뷰어 리스크 최고**

v1 타깃 `z̄(t+Δ) = EMA-인코더(x)[t+Δ]`는 **x[0 .. t+Δ]의 causal 요약** — 따라서
**앵커 자신의 과거** x[0..t]를 포함한다. 즉 장-Δ에서 "미래 예측"의 일부는 "앵커가
이미 인코딩한 걸 회상"하기이며, 이는 **게이트 압력을 희석**: 모델이 slow 인자를
z_slow에 굳이 쓰지 않고도 이미 가진 지속 내용을 복사해 점수를 낼 수 있다.

옵션:
- **(i) causal point 타깃 유지(v1).** 장점: 진짜 t+Δ의 *point* 타깃 — HEPA의
  interval 타깃 대비 우리의 명시적 대비점이자 게이트 "닫아도 무해" 논증의 전제.
  단점: 위 희석; "예측"이 부분적으로 회상.
- **(ii) 타깃 인코더 수용장을 x[t+1 .. t+Δ]로 제한**(윈도우/interval 타깃). 장점:
  회상 지름길 제거, 게이트 압력 선명. 단점: **HEPA의 interval-summary 타깃으로
  표류**하고 **우리 point-타깃 전제와 모순** — 리뷰어가 "HEPA가 됐다"고 할 것.
  또 interval 타깃도 장-Δ에서 fast 내용을 포함, CLAUDE.md §5가 말하는 닫아도-무해
  논증을 깨는 바로 그것.
- **(iii) 정확히 t+Δ의 point 타깃 + t 근방을 제외한 수용장**(예: 타깃은 x[.. t+Δ]
  를 보되 *손실*은 앵커-예측가능분을 뺀 잔차에) — 더 복잡, point 의미 유지, 주의
  필요.

⛔ **결정 필요.** **추천: (i) causal point 타깃 유지**, 희석은 타깃 변경이 아니라
게이트 + 장-Δ 가중 손실로 해결(slow 내용만 살아남는 장 horizon이 그래디언트를
지배하도록). 근거: point-vs-interval 구분은 논문 정체성과 Gating 논증에 핵심;
희석을 고치려 이를 내주면 얻는 것보다 잃는 게 큼. 그러나 가장 도전받기 쉬운
결정이므로, 내가 아니라 당신이 정할 사항.

### B6 — 손실, 옵티마이저, 스케줄 ✅ / 🔁

- **손실 = L2 + λ·xcov, variance floor 없음.** ✅ 확정(D7: vfloor=0에서 붕괴
  없음; 항 제거). λ = 4는 **임의 → 스윕**(v1 기본). 🔁
- **EMA rate 0.996** — 임의 → 스윕(표준 BYOL 범위, 미튜닝). 🔁
- **옵티마이저 AdamW, LR 3e-4** — 임의 → 스윕(미튜닝 기본값). 🔁
- **STEPS 3000, BATCH 64** — 임의; 매직넘버 대신 수렴 체크로 고정(손실 plateau
  까지 학습, 스텝 수 기록). 🔁
- **게이트 소프트니스 W = 4.0 패치** — 임의 → 스윕; 게이트가 소프트-시그모이드

## C. 평가 프로토콜 (v1의 가장 약한 부분)

### C1 — 어느 위치를 probe하나 ⛔

v1은 `enc(x)[:, −1]` = **위치 255**를 probe, 이는 (a) 학습된 앵커 범위 [64,128)
밖이고 (b) 미학습 위치 임베딩(B1). probe가 학습 태스크가 결코 빚은 적 없는 표현을
읽는다.

⛔ **결정 필요(B1과 연동):** **학습된 앵커 범위 안 위치만** probe, 또는 상대 위치
(B1a)면 학습이 보장된 윈도우 끝 고정 오프셋을 probe. **추천:** B1a 채택 시 마지막
위치를 probe; 아니면 학습대 중앙을 probe. 어느 쪽이든 코드에서 **probe 위치 ∈
학습 범위 assert.**

### C2 — probe 라벨 ⛔ (A2와 연동)

v1은 **end-point** 라벨을 probe. A2가 위치별 라벨로 가면 probe는 윈도우 끝이 아닌
**probe 위치의** 라벨을 써야 함. ⛔ **결정 필요 = A2.1.** 추천: 클린 단일-세그먼트
부분집합에서 probe 위치의 위치별 라벨.

### C3 — 그룹 split, disjoint, 누수 방지 ✅

v1이 이건 올바르게 하고 v2도 유지: **그룹 split**(HAPT=피험자, PTB-XL=환자,
XJTU=베어링)으로 어떤 기록도 probe-train과 probe-test에 동시 등장 안 함; **disjoint
(비겹침) 평가 윈도우**; probe는 train 그룹에 적합, held-out 그룹에 채점. Synthetic:
비겹침 윈도우에 연속 시간 컷(앞=train / 뒤=test). ✅ 유지, train/test 윈도우 인덱스
집합이 disjoint임을 명시적으로 assert 추가.

### C4 — 지표 정의 ✅ / 🔁 chance

- **slow-kept** = z_slow에서 slow 인자 probe 점수(활동 F1 / regime acc / life R²).
- **leak** = z_slow에서 *fast* 인자 probe 점수(u R² / accmag R² / phase R²);
  낮을수록 배제 잘됨. 선형 probe AND (v1 정직성 발견에 따라) MLP probe + MINE 보고,
  선형 probe는 배제를 과대평가하므로.
- **chance:** 분류 → 다수클래스/균형-랜덤 baseline 병기(균형 macro-F1 chance =
  1/k); 회귀 → R² chance = 0(train 평균 예측). 0을 암시하지 말고 지표별로 chance를
  명시. ✅
- **RankMe** 유효 랭크를 붕괴 모니터로 보고(제거된 variance floor를 붕괴 *체크*로
  대체). ✅
- 절대 점수, 비율 아님(v1 리뷰어 #4). ✅
